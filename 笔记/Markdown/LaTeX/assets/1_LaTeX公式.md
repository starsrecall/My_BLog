## 简单介绍一下LaTeX公式

  在学术笔记、科研写作、技术博客、在线题库、开源文档等专业内容创作场景中，公式是不可或缺的表达元素。纯文本描述公式（如“x的平方加y的平方等于z的平方”）可读性差、信息密度低，而插入图片格式的公式存在无法复制修改、缩放模糊、排版适配困难等问题。LaTeX作为国际通用的数学排版标准，凭借语法严谨、效果美观、支持复杂公式的优势，已经成为主流Markdown生态的标准功能——用户仅需掌握少量基础语法，就能在Markdown中渲染出符合学术规范的专业公式，大幅提升专业内容的创作效率和呈现质量。
>**如果只需要轻量化使用公式，建议直接使用AI进行生成，但同时建议适当看看LaTex的语法，方便自己diy**

## 平台兼容性基础

### 渲染引擎：MathJax vs KaTeX

  Markdown本身不具备LaTeX公式渲染能力，所有公式渲染都依赖内置的JavaScript引擎实现，目前主流的渲染引擎有两种，特性差异直接决定了不同平台的公式支持能力：

| 对比维度   | MathJax 3                                                    | KaTeX                                                        |
| :--------- | :----------------------------------------------------------- | :----------------------------------------------------------- |
| 开发背景   | 老牌开源引擎，2009年推出，是LaTeX web渲染的事实标准          | 可汗学院2014年推出的轻量级引擎，主打高速渲染                 |
| 命令支持度 | 支持几乎所有LaTeX数学命令，兼容amsmath、amsfonts等绝大多数扩展包，支持自定义宏 | 仅支持常用命令，部分冷门命令和扩展包不兼容，自定义宏能力有限 |
| 渲染速度   | 渲染复杂公式时速度较慢，需要加载较多资源                     | 渲染速度是MathJax的3-5倍，资源占用极低，适合长文档、网页端场景 |
| 渲染效果   | 对复杂公式的排版优化更好，支持细粒度样式调整                 | 排版效果略逊于MathJax，部分特殊公式的间距、对齐存在小问题    |
| 平台适配   | 几乎所有支持LaTeX公式的Markdown平台都默认使用MathJax 3       | 多用于对速度要求高的网页端产品，比如VS Code Markdown插件、部分博客系统，可手动切换为MathJax |

1. **GitHub Flavored Markdown（GFM）**：2022年起原生支持LaTeX公式，使用MathJax 3引擎，支持行内`$...$`、块级`$$...$$`和````math` fenced代码块三种写法，禁用了部分存在安全风险的扩展包命令，是目前兼容性最好的标准。
2. **Obsidian**：默认使用MathJax 3，支持安装KaTeX插件提升渲染速度，允许用户在设置中自定义全局宏、开启扩展包，对本地化、个性化需求的支持度最高。
3. **Typora**：内置MathJax 3，所见即所得的编辑模式对新手友好，支持几乎所有常用命令，中文和公式的混排效果优于其他编辑器。
4. **VS Code**：Markdown All in One插件默认使用KaTeX，可在设置中切换为MathJax，支持自定义渲染配置，适合技术开发场景。
5. **知乎、CSDN、掘金等内容平台**：均使用MathJax 3作为渲染引擎，部分平台禁用了自定义宏、颜色命令等功能，避免用户自定义样式破坏平台排版。
6. **微信公众号**：原生不支持LaTeX公式，需要借助第三方工具将公式转为图片/SVG，或者使用微信公众平台的公式插件实现渲染。
