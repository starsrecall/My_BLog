# 调试和

## 日志

建议在开发时使用日志，包括结构化和非结构化。

一个日志包括

- 追踪
- 调试
- 信息
- 警告
- 错误

> 程序通常有内置的日志功能，可以通过输入**-v**或**-v -v**来得到更多信息。



---

## 反向调试

适用场景，你发现你已经过来产生bug的地方，但是你现在在bug发挥作用的时候，对于小型程序，我们当然可以选择重来，但是大型程序就比较麻烦了，所以就有了反向调试。

如Linux中的**RR**

> **Heisenbugs**
>
> 一类特殊bug，以不确定原理命名。可以理解为，打印调试语句和调试会拖慢进程，这可能会导致bug不被触发，常见于并发程序。

如何使用

```bash
rr record ./XXX #制造一个文件记录信息
```

```bash
rr reply  #加载文件
```

```bash
r #运行
```

```bash
c #继续
```

```bash
b 52 #在52行设置断点
```

```bash
p a[0].id #打印a[0].id
```

```bash
watch a[0].id #监视a[0].id，在改变时中断
```

```bash
reverse-continue #反向
```

```bash
backtrace #可以简写为bt，它会追踪栅，显示你当前所在的函数序列，然后直到运行的地方。
```

## biolatency
